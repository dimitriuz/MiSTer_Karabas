# Stage 2: Machine Completeness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the machine complete per spec §6 stage 2. Turbo 2x/4x/8x must run with no memory wait states; the other items are the 48k/Pentagon screen mode, RTC, mouse and joysticks. DS80, VSync, Pause and NMI already work and are rechecked on the board.

**Architecture:**
- **Clocks.** The SDRAM gets a clock that is always exactly 4x the bus clock. One glitch-free mux picks 112.5 MHz (28.125 MHz mode) or 96.43 MHz (DS80 24.107 MHz mode), and the bus clock is that clock divided by 4. The two clocks therefore keep a fixed phase, even through a DS80 switch.
- **Controller.** A new controller, `sdram_nowait`, serves the CPU synchronously. It opens the row when a T80 M-cycle starts, before the CPU says read or write, so a read is back before T80 latches its data one T-state after RD_n falls. Refresh and the loader port only use slots that cannot collide with a CPU cycle: the M1 refresh phase, bus periods with no CPU enable, and CPU reset.
- **Input devices.** RTC, mouse and joysticks arrive as more frames from the MCU emulation (`mcu_emu`), in the firmware's documented protocol, so the machine side needs no change.

**Tech Stack:** VHDL-93 and SystemVerilog, Quartus 17 (Docker, `tools/build.sh`), GHDL `--std=93c -fsynopsys` and Icarus `-g2012` through `tools/sim.sh`, Python 3 tools with `unittest`.

**Spec:** `docs/superpowers/specs/2026-11-02-karabas-profi-mister-port-design.md` (§5.2 memory, §5.3 clocks, §5.9 OSD, §6 stage 2). Stage 1 results and review: `docs/dev/stage1-results.md`, `.superpowers/sdd/2026-11-02-stage1-skeleton-and-boot/final-review.md`.

## Review Focus

1. **A DS80 switch while the CPU runs at 8x.** The switch happens on a CPU `OUT` and the next fetch follows at once. Expected: no wrong byte, and no refresh or loader access hitting a CPU cycle. Test: Task 1 tb_clock (phase across a switch) and Task 4 tb_turbo_nowait run with DS80 toggled mid-program.
2. **Read-modify-write on one address** (`INC (HL)`, `LDIR` onto itself). A write M-cycle can follow a read of the same address with no address change. Expected: the write lands. Test: Task 3 case `rmw_same_address`, and Task 4's program includes `INC (HL)`.
3. **Long WAIT stretches at 8x** (48k-mode contention, IDE/FDC WAIT). These hold T2, so there is no M1 refresh window for a while. Expected: the refresh backlog stays bounded and the data held in `dout` stays valid through the wait. Test: Task 3 case `wait_in_t2` with a 20 µs WAIT.
4. **Loader bytes arriving before the SDRAM is initialised**, or while the CPU runs at 8x (the stage-4 file loads). Expected: no byte lost. Test: Task 3 case `portb_under_8x` and Task 4's `mem_ready` gate in mcu_emu.

### Task 2: SDRAM chip model with a timing checker

**Files:**
- Create: `sim/models/sdram_chip.vhd`, `sim/tb_sdram_chip.vhd`, `sim/run_tb_sdram_chip.sh`; add to `sim/run_all.sh`

**Interfaces:**
- Produces entity `sdram_chip`.
  - Generics: `T_CK_NS : real := 8.888889`, `CL : integer := 2`, `TRCD : integer := 2`, `TRP : integer := 2`, `TRAS : integer := 5`, `TRC : integer := 8`, `TRFC : integer := 8`, `TWR : integer := 2`, `REFRESH_US : real := 64000.0`, `ROWS : integer := 8192`. Timing limits are in clock cycles of the clock the model is given.
  - Ports, as the MiSTer pins: `clk` (the SDRAM_CLK pin: the clk_mem inverted, as the altddio in `Karabas_Profi.sv` makes it), `cke`, `cs_n`, `ras_n`, `cas_n`, `we_n`, `ba(1:0)`, `a(12:0)`, `dqm(1:0)`, `dq(15:0)` inout.
  - Outputs for testbenches: `violations : out natural` (count) and `refreshes : out natural`.
  - Shared memory: a package array `sdram_chip_mem` of 2 MiB bytes (the machine map) that testbenches can preload and inspect.

- [ ] **Step 1: The model.** Decode NOP/ACTIVE/READ/WRITE/PRECHARGE/AUTO REFRESH/LOAD MODE per bank on the rising edge of `clk`.
  - A10 on READ/WRITE = auto precharge. Burst length 1. CAS latency from the mode register (must be 2).
  - READ data drives `dq` from CL clock edges after the command until the next edge, then 'Z'. `dqm` masks bytes on writes.
  - Each of these is a violation, reported with `report ... severity error` naming the rule and the time, and counted in `violations`:
    - ACTIVE to an open bank;
    - READ/WRITE to a closed bank, or before TRCD;
    - PRECHARGE before TRAS from ACTIVE;
    - ACTIVE before TRP after PRECHARGE (auto precharge starts after the burst, and for writes after TWR);
    - ACTIVE before TRC from the previous ACTIVE to the same bank;
    - REFRESH with any bank open, or another command before TRFC after a REFRESH;
    - any command during the 100 µs power-up (not counting NOP);
    - `dq` driven by the FPGA (not 'Z') while the model drives it;
    - fewer than ROWS refreshes in any sliding window of REFRESH_US.

    For the last one, check the count at every refresh: the time since the ROWS-th previous refresh must be ≤ REFRESH_US.

  - a legal init (100 µs NOP, PRECHARGE ALL, 2 × REFRESH, LOAD MODE CL2 BL1) followed by write/read of a byte in each half of the word gives `violations = 0` and the right data on `dq` at CL;
  - each of the nine rules above, broken once in its own sequence, increments `violations` by exactly one.

  Print `tb_sdram_chip: PASS`/`FAIL`.

### Task 3: `sdram_nowait`, the no-wait controller

**Files:**
- Create: `rtl/mem/sdram_nowait.vhd`, `sim/tb_sdram_nowait.vhd`, `sim/run_tb_sdram_nowait.sh`; add to `files.qip` and `sim/run_all.sh`

**Interfaces:**
- Consumes: Task 1 `BUS_PHASE`, `RESET_MEM`; Task 2 `sdram_chip`.
- Produces entity `sdram_nowait`. Ports:
  ```vhdl
  clk_mem   : in  std_logic;                     -- 112.5 / 96.43 MHz
  reset     : in  std_logic;                     -- RESET_MEM (clk_mem, sync)
  bus_phase : in  std_logic_vector(1 downto 0);  -- clock.vhd BUS_PHASE
  ready     : out std_logic;                     -- init done (clk_mem)
  -- CPU port: clk_bus-domain signals, read only on bus_phase = "10"
  cpu_reset_n : in std_logic;                    -- the T80 RESET_n
  cpu_ena   : in  std_logic;                     -- ENA_CPU (the value of this clk_bus period)
  cpu_ts    : in  std_logic_vector(2 downto 0);  -- T80 TState (TS_O)
  cpu_mc    : in  std_logic_vector(2 downto 0);  -- T80 MCycle (MC_O)
  cpu_mreq_n, cpu_rd_n, cpu_wr_n, cpu_iorq_n : in std_logic;
  cpu_addr  : in  std_logic_vector(20 downto 0); -- memory.vhd's paged byte address
  cpu_wr_en : in  std_logic;                     -- 1 = this address may be written (RAM)
  cpu_din   : in  std_logic_vector(7 downto 0);  -- T80 DO
  cpu_dout  : out std_logic_vector(7 downto 0);  -- clk_mem register, read by the T80 at the latch edge
  -- port B (loader now, GS in stage 3): clk_bus domain, read on bus_phase = "10"
  b_req     : in  std_logic;                     -- level; one access per rising edge of b_req
  b_we      : in  std_logic;
  b_addr    : in  std_logic_vector(20 downto 0);
  b_din     : in  std_logic_vector(7 downto 0);
  b_dout    : out std_logic_vector(7 downto 0);
  b_done    : out std_logic;                     -- toggles when the access is complete
  -- SDRAM pins (SDRAM_CLK is made by the top's altddio from clk_mem)
  sd_ba : out std_logic_vector(1 downto 0); sd_a : out std_logic_vector(12 downto 0);
  sd_dqm : out std_logic_vector(1 downto 0); sd_ras_n, sd_cas_n, sd_we_n : out std_logic;
  sd_dq : inout std_logic_vector(15 downto 0)
  ```

**Design (exact; the header comment of the file must state it):**

*Timing facts this rests on (T80s.vhd, T2Write = 1):* At a CEN edge, T80s changes `TS`/`MC`/`A` for the next T-state.
- RD_n (reads) and WR_n (writes) go low at the edge that ends T1 (call it E1).
- The T80 latches DI (and the opcode) at the edge that ends T2 (E2), when Wait_n = 1.
- In M1, T3 and T4 are the refresh phase: MREQ_n and RFSH_n are low and there is no CPU data access.
- At turbo 11 a T-state is one clk_bus period, which is 4 clk_mem. So from the edge that starts T1 (E0) to the latch edge (E2) there are exactly 8 clk_mem.

*Samples.* The controller reads clk_bus-domain inputs only on the clk_mem edge where `bus_phase = "10"`. That is 2 clk_mem after each clk_bus rising edge, so every clk_bus→clk_mem path has 2 clk_mem periods (sdc multicycle in Task 4). Call such an edge a *sample*. Commands may be issued on any clk_mem edge, but only from registered state. Name the sample after the clk_bus edge it follows. At turbo 11, with M-cycle start E0 at clk_mem t = 0:
- the sample after E0 is t = 2;
- the sample after E1 is t = 6;
- E2 is t = 8;
- the sample after E2 is t = 10.

Times below are in clk_mem from **the start sample S0**.

*Address mapping (as `rtl/mem/sdram.sv`, kept for continuity):* word address = addr[20:1]; byte lane = addr[0], lane 0 = DQ[7:0]; BA = "00"; row = addr[13:1] (13 bits); column = addr[20:14] in `sd_a(6 downto 0)` with `sd_a(8 downto 7) = "00"`, `sd_a(9) = '0'`, `sd_a(10)` = auto precharge. On READ and WRITE the byte mask goes out twice, exactly as sdram.sv does: on `sd_dqm` (the top wires it to SDRAM_DQMH/DQML) **and** on `sd_a(12)` = DQMH, `sd_a(11)` = DQML (some MiSTer SDRAM boards take the mask from A12/A11). A read reads both lanes (mask "00"); a write masks the other lane. Writes drive `sd_dq` with the byte on both lanes; `sd_dq` is 'Z' at all other times.

*Init:*
- At reset: NOPs for 100 µs. Count the cycles at the 112.5 MHz rate, `INIT_CLKS = 11250 + 64`, which also covers 96.43 MHz.
- Then PRECHARGE ALL, then 2 × AUTO REFRESH TRFC apart, then LOAD MODE (CL2, BL1, single write).
- `ready` goes to 1 after that. Until then, CPU events are ignored and port B waits.

*CPU M-cycle (the only path for CPU data):*
1. **Start.** At a sample where `cpu_ts = "001"` and the previous sample's `cpu_ts /= "001"`, and `cpu_reset_n = '1'`:
   - issue ACTIVE (row of `cpu_addr`) at S0;
   - latch `cpu_addr` and `cpu_wr_en`;
   - issue READ without auto precharge at S0 + 2.
   - The bank is idle at S0 and TRC has elapsed (assert this in simulation; it is the schedule's invariant).
2. **Read data.** Capture the read byte into `cpu_dout` at S0 + 5. That is the CL2 capture edge of a READ issued at S0 + 2, with SDRAM_CLK inverted. Confirm it against `rtl/mem/sdram.sv`'s `data_ready_delay` and the chip model; if the model says a different edge, use the model's and report it. `cpu_dout` then holds until the next capture.
3. **Resolve** at the first later sample (S0 + 4, S0 + 8, …) where one of these holds:
   - `cpu_wr_n = '0'` and `cpu_mreq_n = '0'` (a write): latch `cpu_din` at that sample. Issue WRITE with auto precharge at max(that sample + 1, S0 + 6), with the byte lane's DQM, only if the latched `cpu_wr_en = '1'`; otherwise PRECHARGE. Also update `cpu_dout` with the written byte if the latched address equals itself (it does), so a read of a just-written byte is right.
   - `cpu_rd_n = '0'` or `cpu_iorq_n = '0'` (a read or an I/O cycle): PRECHARGE at max(that sample + 1, S0 + 5).
   - `cpu_ts >= "011"` with none of the above (an M-cycle without a memory access): PRECHARGE at that sample + 1.
4. **Idle** again at max(ACTIVE + TRC, PRECHARGE + TRP, WRITE + 2 + TRP).

   At turbo 11 that is S0 + 7 for reads and S0 + 10 for writes, before the next possible start sample S0 + 12. Assert in simulation that every start sample finds the bank idle.

*Free windows (refresh and port B), only when idle:*
- **(a)** the first sample with `cpu_mc = "001"` and `cpu_ts = "011"` (the M1 refresh phase);
- **(b)** any sample with `cpu_ena = '0'`: the T80 cannot change state at the next clk_bus edge, so no start sample can come before 8 clk_mem from now;
- **(c)** any sample with `cpu_reset_n = '0'`.

In a window, issue at that sample (call it W):
- AUTO REFRESH if `owed > 0` (then `owed - 1`);
- else a port B access if one is pending: ACTIVE at W, then READ or WRITE with auto precharge at W + 2, read data captured at W + 5 into `b_dout`, `b_done` toggles at W + 6.

Both finish by W + 8, when a CPU start is allowed again.

`owed` increments every `REFRESH_CLKS = 700` clk_mem (6.2 µs at 112.5 MHz, 7.26 µs at 96.43 MHz) and saturates at 15. A sim assertion fails if it ever reaches 9.

*Port B pending:* set on a rising edge of `b_req` seen at a sample; cleared when its access is issued. A second rising edge while still pending is an error: a sim assertion, plus a sticky `b_overrun` bit (add `b_overrun : out std_logic`).

**Frame formats** (firmware `docs/protocol.md` §4 and `lib/rtc/rtc.c`; upstream `kg_mcu_hid.v`, `kg_mcu_rtc.v`):
- **Mouse**, on every toggle of `ps2_mouse[24]`:
  - `02 00 dx`, `02 01 dy`, `02 02 dz`, `02 03 buttons`, in that order (the buttons frame ends a report);
  - `dx` = the 9-bit two's complement {ps2_mouse[4], ps2_mouse[15:8]} clamped to −127..127;
  - `dy` = **minus** {ps2_mouse[5], ps2_mouse[23:16]} clamped (PS/2 Y is up-positive, USB Y down-positive);
  - `dz` = ps2_mouse_ext[3:0] (wheel delta, low 4 bits; confirm the field in `sys/hps_io.sv`);
  - `buttons` = {5'b0, ps2_mouse[2], ps2_mouse[1], ps2_mouse[0]}, so bit0 left, bit1 right, bit2 middle.
- **Joysticks:**
  - CONF_STR gets `J1,A,B,C,X,Y,Z,Start,Mode;`, so MiSTer `joystick_n` bits are [0] right, [1] left, [2] down, [3] up, [4] A, [5] B, [6] C, [7] X, [8] Y, [9] Z, [10] Start, [11] Mode;
  - the Karabas 13-bit word is bit 0 connected (always 1), 1 up, 2 down, 3 left, 4 right, 5 start, 6 A, 7 B, 8 C, 9 X, 10 Y, 11 Z, 12 mode;
  - when either word changes, send `03 00 lo(L)`, `03 01 hi(L)`, `03 02 lo(R)`, `03 03 hi(R)`, with L from `joystick_0` and R from `joystick_1`.
- **RTC** (MC146818A, core.json `rtc_mode` 0):
  - MiSTer `RTC` bytes are BCD: [7:0] sec, [15:8] min, [23:16] hour, [31:24] date, [39:32] month, [47:40] year, [55:48] weekday 0-6. Send weekday + 1, as TSConf_MiSTer `rtl/periph/mc146818a.v` does.
  - `is_bcd` starts at 1. Every reply frame with command `FA` and address `0B` sets `is_bcd = ~data[2]`. Other `FA` replies (CPU writes of time or CMOS) are ignored: MiSTer's clock is the time source. Say so in the README.
  - Time frames: `FA 00 s`, `FA 02 m`, `FA 04 h`, `FA 06 wd`, `FA 07 d`, `FA 08 mo`, `FA 09 y`, in BCD, or binary when `is_bcd = 0` (convert BCD → binary in the FPGA).
  - **Start sequence:** after the switch frames and before the keyboard clear, send the time frames, then `FA 01 00`, `FA 03 00`, `FA 05 00`, `FA 0A 26`, `FA 0B {is_bcd ? 02 : 06}`, `FA 0C 00`, `FA 0D 80`, then `FA r FF` for r = 0x0E..0xFF.
  - **Run loop:** the time frames every 500 ms (`RTC_CLKS = 25_000_000` at 50 MHz), and also right after `RTC[64]` toggles for the first time.
- **Priority in the run loop:** switches > keyboard > mouse > joystick > RTC > triggers > NOP. A pending report of each kind is kept as its latest value; frames are never reordered within a report.
