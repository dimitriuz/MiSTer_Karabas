# Stage 3: Sound Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every upstream sound source works on MiSTer (spec §6 stage 3): General Sound with 2 MB, TurboSound FM, SAA1099, OPL2, Covox/Soundrive, beeper, the PSG mix modes, and MIDI out to an mt32-pi on the USER port.

**Architecture:**
- **Already in the build, only checked on the board:** TurboSound FM (`turbosound`, two jt03), SAA1099, OPL2 (`opl2_top`), Covox, beeper, `audio_mixer`. Stage 2 heard the beeper and the AY.
- **General Sound** is off today (`ENABLE_GS(0)`): `memory.vhd` stubs its RAM (`GS_DO <= x"FF"`) and drops the GS ROM bytes of the loader. Upstream gives the GS a whole SDRAM chip of its own; here it would have to share the one SDRAM with the no-wait CPU controller, whose spare slots shrink to one per instruction at turbo 8x. So the GS memory moves to the DE10-Nano's **DDR3** (sys `DDRAM_*`), the way Sorgelig's ZX-Spectrum core does it: the low 64 KB of the GS address space (32 KB ROM + RAM pages 2/3, where the GS code runs) in BRAM with no wait, the rest in DDR3 behind a one-line read cache, with `GS_WAIT_N` holding the GS Z80 while DDR3 answers. The CPU's SDRAM path is untouched.
- **The GS clock relation.** Upstream's `gs.v` reads the host CPU bus (`#B3/#BB` ports) directly on `clk_gs`. On the Karabas Go, `clk_bus` in the 28 MHz mode is the same PLL clock as `clk_gs` through a BUFGMUX, so that is synchronous logic. Here `clk_bus` = `clk_mem / 4` from a fabric divider whose phase against `clk_gs` is whatever the reset release (or the last DS80 switch) left: 1 of 4. Task 1 makes the divider re-align itself to `clk_gs` while DS80 = 0, by stretching one low phase of the bus clock at a time, so STA's assumption (the generated `clk_bus28` starts on the edge where `clk_gs` rises) is what the hardware does. With DS80 = 1 the host cannot reach the GS (`gs.v` gates `gs_sel` with DS80) and `clk_gs` is cut asynchronous against the 96/24 MHz pair.
- **MIDI (owner, 2026-11-08: "Mt32-pi should go to usual mister mt32 path, so I can use remote mt32-pi for example via uart/network"):** upstream's `MIDI_TX` (TurboSound AY port A bit 2, a 31250-baud line the software drives) goes two ways, as in the owner's pico-speccy Plan 4 (`~/repo/MiSTer_pico-speccy/fpga/rtl/ps_mt32_mix.sv`, rulings R-P4-11/R-P4-13):
  - **MidiLink:** to `UART_TXD` when the MiSTer menu's UART mode is MIDI (`uart_mode == 3`; CONF_STR header `UART31250,MIDI`). Main_MiSTer's MidiLink then routes it to a remote mt32-pi over the network, a software synth (MUNT/FluidSynth) or USB MIDI.
  - **USER port:** to `sys/mt32pi.sv` for an mt32-pi plugged into the USER port, its I2S audio mixed into `AUDIO_L/R` in the `CLK_AUDIO` domain.
  The UART is otherwise idle until stage 5 (serial), which adds its channels to the other UART modes.

### Task 2: `gs_mem`, the GS memory on BRAM and DDR3

**Files:**
- Create: `rtl/mem/gs_mem.sv`, `sim/models/ddram_model.sv`, `sim/tb_gs_mem.sv`, `sim/run_tb_gs_mem.sh`

**Interfaces:**
- Produces:
```systemverilog
module gs_mem (
    input  wire        clk,         // CLK_GS 28.125 MHz; the DDRAM_CLK too
    input  wire        reset,       // async; synchronised inside (2 FF)
    input  wire [20:0] a,           // GS bus (gs.v MA), clk domain
    input  wire  [7:0] din,         // GS write data (MDO)
    input  wire        rd,          // = ~MRD_n (level)
    input  wire        wr,          // = ~MWE_n (level)
    output wire  [7:0] dout,        // to MDI
    output wire        wait_n,      // to GS_WAIT (T80 WAIT_n)
    input  wire [20:0] ldr_a,       // loader byte (other clock): address,
    input  wire  [7:0] ldr_d,       //   data, stable before ldr_tgl moves
    input  wire        ldr_tgl,     //   toggles once per byte
    input  wire        ddr_busy,
    output wire  [7:0] ddr_burstcnt,
    output wire [28:0] ddr_addr,
    input  wire [63:0] ddr_dout,
    input  wire        ddr_dout_ready,
    output wire        ddr_rd,
    output wire [63:0] ddr_din,
    output wire  [7:0] ddr_be,
    output wire        ddr_we
);
```

Behaviour (the header comment states all of it):
- `low = (a[20:16] == 0)`: a 64 K × 8 inferred RAM. Each clock: `q <= ram[a[15:0]]`; write `din` when `wr && low`. Loader: `ldr_tgl` through 2 FF, and on a change of the second stage write `ldr_d` at `ldr_a[15:0]` if `ldr_a[20:16] == 0` (the GS ROM, 32 KB at 0); other loader addresses are ignored. The loader write takes the RAM port over GS writes (the GS is in reset while the loader runs).
- High addresses (`!low`) in DDR3 at byte address `0x3000_0000 + a`: `ddr_addr = {4'b0011, 7'd0, a[20:3]}`, `ddr_burstcnt = 1`.
- A one-line read cache: `line[63:0]`, `tag[17:0]`, `valid`. `hit = valid && tag == a[20:3]`.
- `dout = low_r ? q : line[8*a[2:0] +: 8]`, `low_r` = `low` registered on the same edge as `q`.
- `wait_n = !(!low && ((rd && !hit) || (wr && !wdone)))`: combinational, so the T80 sees WAIT in the first T2.
- Read miss: assert `ddr_rd` with the address; drop it on the first clock with `!ddr_busy` (Avalon accept); on `ddr_dout_ready` load `line`, `tag`, `valid = 1`.
- Write: assert `ddr_we` with `ddr_din = {8{din}}`, `ddr_be = 8'b1 << a[2:0]`; drop on accept and set `wdone`; `wdone` clears when `wr` falls. On issue, if `valid && tag == a[20:3]`, write the byte into `line` too (write-through, no stale line).
- Reset: no request, `valid = 0`, `wdone = 0`.

`ddram_model.sv` (sim only): 2 MB as 262144 × 64-bit words indexed by `ddr_addr[17:0]`. It checks `ddr_addr[28:18] == {4'b0011, 7'd0}` and `ddr_burstcnt == 1` on every request. Parameters: `LAT` (read latency in clocks after accept) and `BUSY_PCT` (pseudo-random BUSY). It accepts on `(rd|we) && !busy`, applies BE on writes and pulses `ddr_dout_ready` for one clock with the word `LAT` clocks later. It has a `force_busy` input for the long-busy case.

- [ ] **Step 1: Write `sim/tb_gs_mem.sv`** with a reference byte array of 2 MB and these cases, each printing its name and `ok` or `FAIL <case> <addr> <got> <want>`:
  - `loader_rom`: the loader on its own 24.107 MHz clock writes 32768 bytes (pattern `addr*7+3`), one byte per 64 loader clocks; then GS reads of 0x0000..0x7FFF return them with `wait_n` never 0.
  - `bram_ram`: write and read back 0x8000..0xFFFF (a stride of 97), no wait.
  - `ddr_random`: 2000 random reads and writes over 0x10000..0x1FFFFF with `LAT` 3..20 and `BUSY_PCT = 30`; every read equals the reference.
  - `read_hit`: two reads in one 8-byte line. The second has `wait_n = 1` in its first cycle.
  - `write_hits_cached_line`: read a line, write one of its bytes, read that byte: the new value.
  - `long_busy`: `force_busy` for 300 clocks during a write and then during a read; both complete correctly, `wait_n` stays 0 meanwhile.
  - The GS bus is driven like the T80 at CE = 1: address and data set on one edge, `rd`/`wr` raised on the next, `dout` taken and the strobe dropped on the first edge where `wait_n` was 1.
  - End: `tb_gs_mem: PASS` or `tb_gs_mem: FAIL`.
- [ ] **Step 2: `sim/run_tb_gs_mem.sh`** in the style of `run_tb_mcu_input.sh` (Icarus `-g2012`, hop into the sim image, the verdict as the last line). It needs no prepared upstream. Run it: FAIL (no `gs_mem`).

### Task 4: MIDI: MidiLink on the UART and MT32-pi on the USER port

**Interfaces:**
- Produces:
```systemverilog
module mt32_mix (
    input  wire               clk,           // CLK_AUDIO
    input  wire signed [15:0] emu_l, emu_r,  // profi AUDIO_L/R (clk_bus domain)
    input  wire signed [15:0] pi_l,  pi_r,   // mt32pi mt32_i2s_l/r (CLK_AUDIO)
    input  wire               pi_available,  // mt32pi mt32_available
    input  wire               pi_disable,    // status[27]: 1 = "Use MT32-pi: No"
    input  wire               midi_tx,       // profi MIDI_TX
    input  wire        [ 7:0] uart_mode,     // hps_io uart_mode (3 = MIDI)
    output reg  signed [15:0] audio_l, audio_r,
    output wire               midi_tx_to_pi,
    output wire               uart_txd       // UART_TXD, idle high
);
```
  - `emu_*` pass two `clk` registers (crossing from clk_bus), then `audio_x <= sat16(emu_x_s2 + (pi_on ? pi_x : 0))`, `pi_on = pi_available & ~pi_disable`. `sat16` is the signed 17-bit sum clipped to 16'h7FFF / 16'h8000 when its top two bits differ, as in pico-speccy's `ps_mt32_mix.sv`.
  - `midi_tx_to_pi = midi_tx | (pi_available & pi_disable)`, combinational.
  - `uart_txd = (uart_mode == 8'd3) ? midi_tx : 1'b1`, combinational: the MidiLink route. Main_MiSTer sends 3 only for "MIDI"; the other modes give Linux the UART (see the `ps_mt32_mix.sv` header). It carries the unmuted line: "Use MT32-pi = No" mutes only the USER-port Pi.

- CONF_STR, directly after `"P1O[7],VSync,50 Hz,60 Hz;",`:
  `"P2,MT32-pi;", "P2O[27],Use MT32-pi,Yes,No;", "P2O[28],Synth,Munt,FluidSynth;", "P2O[30:29],Munt ROM,MT-32 v1,MT-32 v2,CM-32L;",`
